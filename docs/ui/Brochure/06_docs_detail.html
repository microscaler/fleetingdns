Zero-Trust Architecture

What is Zero-Trust?

Zero-Trust is a security framework that requires all users, whether inside or outside the organization's network, to be authenticated, authorized, and continuously validated before being granted or maintaining access to applications and data. This approach moves away from the traditional "trust but verify" model to a "never trust, always verify" stance.

Key Insight

In a Zero-Trust model, the network location of a user, device, or resource is no longer the primary factor in determining security posture. Instead, security decisions are made on a per-request basis with strict identity verification.

Traditional security models operate on the assumption that everything inside the organization's network should be trusted. However, this approach has proven inadequate in today's complex threat landscape, where insider threats, sophisticated phishing attacks, and supply chain compromises are increasingly common.

Core Principles

Verify Identity

All users must be authenticated, authorized, and validated before accessing resources, regardless of location.

Least Privilege

Users should only have access to the resources they need to perform their job functions and nothing more.

Continuous Monitoring

All resource access is monitored and logged, with anomalies triggering alerts and potentially revoking access.

Micro-Segmentation

Network segments are broken down into smaller zones with separate access requirements to minimize lateral movement.

Zero-Trust vs. Traditional Security

Traditional Approach Zero-Trust Approach
Trust internal network by default Trust nothing by default
Perimeter-focused security Identity-focused security
Authenticate once at entry Continuous authentication
Broad access once inside Least privilege access

Implementation in EDF

EDF implements Zero-Trust principles at its core, providing a secure tunneling solution that maintains strict access controls for all connections. Here's how EDF enforces Zero-Trust security:

Mutual TLS Authentication (mTLS)

EDF uses mTLS for bidirectional authentication, ensuring both the client and server verify each other's identity. Certificates are automatically rotated every 30 minutes, minimizing the impact of potential credential theft.

Certificate Rotation Bidirectional Auth X.509 Certificates

DNSSEC Signing

All EDF domains are DNSSEC-signed, preventing DNS spoofing attacks and ensuring that users connect to legitimate EDF infrastructure rather than malicious impersonators.

DNS Security Anti-spoofing

OIDC Integration

EDF integrates with OpenID Connect (OIDC) providers, allowing enterprises to leverage their existing identity infrastructure for user authentication and authorization.

Identity Federation SSO JWT Tokens

Comprehensive Audit Logging

Every access attempt, successful or not, is logged with detailed context information, enabling security teams to monitor for suspicious activity and conduct forensic analysis when needed.

Access Logs Anomaly Detection

Authentication Flow

The EDF authentication flow combines multiple security layers to ensure comprehensive protection:

EDF Zero-Trust Authentication Flow

1

Initial Connection Request

Client initiates connection to an EDF tunnel endpoint.

2

mTLS Handshake

Client and server exchange and validate certificates. Both sides must present valid, unexpired certificates.

3

Identity Verification

If OIDC is configured, the client's identity token is validated against the configured identity provider.

4

Authorization Check

EDF verifies that the authenticated identity has permission to access the requested tunnel.

5

Rate Limiting & Policy Enforcement

Additional security policies such as rate limiting and time-based access controls are applied.

6

Connection Established

If all checks pass, the secure tunnel connection is established and traffic begins flowing.

CLI Example 
# Create a tunnel with enhanced security
$ edf tunnel 8080 --oidc-provider=okta --require-auth --rate-limit=100

✓ Tunnel created with Zero-Trust security!
✓ URL: https://dev-ab12c.edf.dev
✓ Security: mTLS + OIDC authentication required
✓ Certificate rotation: Every 30 minutes
✓ Access logs: Enabled and streaming to configured destination

Best Practices

Even with Zero-Trust architecture, security depends on proper implementation and maintenance. Follow these best practices to maximize security.

Enable OIDC Integration

Whenever possible, integrate EDF with your organization's identity provider through OIDC to leverage existing user management and authentication policies.

Implement Rate Limiting

Configure appropriate rate limits for your tunnels to prevent abuse and potential denial-of-service attacks.

Monitor Audit Logs

Regularly review EDF audit logs and set up alerts for suspicious activities, such as access attempts outside normal business hours or from unusual locations.

Use Time-Based Access Controls

Limit tunnel access to specific time windows when legitimate use is expected, reducing the attack surface during off-hours.

Implement IP Allowlisting

For highly sensitive tunnels, consider restricting access to specific IP ranges, adding another layer of security beyond authentication.
